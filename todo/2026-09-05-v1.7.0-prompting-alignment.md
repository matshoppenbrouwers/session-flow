# Phase 17: session-flow 1.7.0 — prompting alignment

**Design Doc**: `plans/2026-09-05-v1.7.0-prompting-alignment.md`
**Goal**: Land the plan's thirteen changes as twelve session-sized tasks and ten commits: two new
skills, confidence labels in place of thresholds, the sanitizer folded into the simplifier, the
test-first framing dropped, the grammar rationale in one reference, shared backlogs, and 1.7.0.

Each task names the plan change it implements (C1…C13). **Read that section of the design doc
before starting the task** — it carries the exact wording, and where it quotes wording verbatim
that wording is the deliverable, not a paraphrase of it.

Three house rules from §0 of the plan apply to every task here:

- **Repo-agnostic.** Nothing added may name a user, company, repo, framework, or folder layout.
- **Targeted edits, not rewrites.** Change the lines the plan names; leave the rest.
- **No new machinery.** Do not add verification steps, review passes, or subagent dispatches
  beyond what a task states.

## Deviations from the design doc

Found by surveying the repo against the plan. Each is a correction the implementer needs; none
changes the plan's intent.

1. **The `sanitiz` acceptance grep cannot reach zero.** `grep -rn 'sanitiz'` also matches
   legitimate security vocabulary that must stay: `agents/code-reviewer.md:37` (path traversal
   without sanitization), `agents/security-auditor.md:30` and
   `skills/security-liability-audit/SKILL.md:39` (unsanitized AI output),
   `skills/security-liability-audit/references/technical-security.md:33,35,265`,
   `references/legal-liability.md:364`. 17B-4 uses a narrower test that targets the agent name and
   the workflow step instead. Do not strip the security wording to satisfy a grep.
2. **The `80%` grep also catches a duplication heuristic.** `agents/code-simplifier.md:48` says
   ">80% similarity" — a similarity threshold, not a confidence gate. 17B-1 rewords it so the
   acceptance grep reads only confidence gates.
3. **C4 misses two sites.** `skills/security-liability-audit/references/technical-security.md:253`
   ("Only report findings at >= 80% confidence") and `README.md:183` ("confidence-based filtering
   (80% gate)") carry the same gate the change removes. 17B-1 includes both. The §8 hard
   exclusions stay as written, per C4.
4. **C4's own acceptance passes only after 17B-4.** `agents/code-sanitizer.md:13,99` hold the last
   two thresholds and that file is deleted by C6, so 17B-1's test excludes it.
5. **Four of C10's "Path Resolution blocks" are inline sentences, not blocks.** Only add-task,
   groom, next, gatekeeper (`## Path & Context Resolution`) and init have headed blocks;
   task-planning, research-design, verify and post-implementation reference `.session-flow.json`
   inline. 17C-3 names the exact lines.
6. **`marketplace.json` carries the version twice** (lines 8 and 15), so §4's `grep -c '1.7.0'`
   expects 1 but will read 2. 17D-2 checks both sites deliberately.
7. **`CITATION.cff` also carries the counts** in its abstract ("13 skills and 7 agents") and a
   `date-released` field. C13 names neither; 17D-2 updates both.
